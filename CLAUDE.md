# CLAUDE.md — BlissTime (робоча назва)

## Що це за проект

Гібридна платформа для б'юті-індустрії України:

1. **SaaS-кабінет** для майстрів, салонів і брендів — букінг, CRM, Telegram-сповіщення (`app.domain.ua`)
2. **Публічний агрегатор** — каталог майстрів і салонів з пошуком, що наповнюється автоматично з даних кабінетів (`domain.ua`)

Стратегія: **tool first, marketplace second**. Кабінет продається за підписку, агрегатор — безкоштовна вітрина для майстрів і джерело SEO-трафіку.

## Фокус ринку (жорстке правило)

**Тільки б'юті на перші 12+ місяців**: нігті, брови/вії, волосся (перукарі, барбери, колористи), косметологія, макіяж, масаж, тату/перманент, епіляція.

Таксономія в БД проектується розширюваною (щоб колись додати інші вертикалі), але жодного UI, маркетингу чи фіч для СТО, репетиторів, клінінгу тощо. Resource-based scheduling (бокси, підйомники), абонементи та курсові пакети — поза scope.

## Позиціонування (чим ми кращі за конкурентів)

Конкуренти: zapys.beauty (мобільний застосунок), zapys.tech (кастомні Telegram-боти), Altegio (важка система для салонів).

1. **Web-first, zero friction**: клієнт записується за 10 секунд у браузері з лінка в Instagram — без застосунку, без реєстрації, без переписки в Direct
2. **SEO-агрегатор = безкоштовний канал клієнтів**: сторінки `/kyiv/manicure/` приводять майстру людей з Google. Аргумент продажу: "платиш за кабінет — клієнтів з Google отримуєш безкоштовно"
3. **Продаємо не календар, а гроші майстру**: waitlist, Камбекер і рейтинг надійності напряму повертають клієнтів і рятують доходи від no-show
4. **Ніша "між"**: соло-майстри, яким Altegio задорогий, і мікрокоманди 2–4 крісла, яких ніхто не обслуговує

Формула лендінгу: для клієнток — "запишись за 10 секунд, без дзвінків і застосунків"; для майстрів — "клієнти з Google та Instagram записуються самі, а ті, що були — повертаються".

## Технічний стек

- **Framework**: Next.js 15 (App Router), TypeScript strict mode
- **UI**: React, Tailwind CSS, shadcn/ui
- **База даних**: PostgreSQL (Supabase або Neon) + Prisma ORM
- **Auth**: Auth.js (NextAuth v5) — email/password + Google OAuth
- **Сповіщення**: Telegram Bot API (grammY); Viber — у беклозі; SMS — платний fallback пізніше; WhatsApp не робимо
- **AI**: OpenAI API (GPT-4o / GPT-4o-mini, structured outputs) — імпорт прайсу, Камбекер-діалоги
- **Платежі**: онлайн-оплат немає (у клієнтів може не бути ФОП). Замість цього — порада майстру попросити передоплату для ризикових/нових клієнтів (offline). Підписки майстрів — пізніше
- **Хостинг**: Railway (персистентний Node-сервер, не serverless)
- **Мова інтерфейсу**: українська (i18n-ready структура, але без перекладів на старті)

## Архітектурні принципи

1. **Одна БД, два фасади.** Кабінет і агрегатор — один Next.js проект (route groups: `(app)` і `(public)`), спільна модель даних.
2. **Публічні сторінки = SEO-актив.** Сторінки `/[misto]/[kategoria]/` і профілі майстрів — SSG/ISR з ревалідацією. Метадані, structured data (schema.org LocalBusiness, Service), sitemap. Mobile-first, PageSpeed 90+.
3. **Жорстка таксономія послуг.** Кожна послуга майстра прив'язана до категорії з фіксованого дерева (`nails.manicure.gel`), вільна назва — тільки як display name.
4. **Мультитенантність з першого дня.** Схема підтримує соло-майстра, салон і бренд, навіть якщо UI для салонів з'явиться пізніше.
5. **Таймзони і слоти — тільки через date-fns-tz, все зберігається в UTC.** Календарна логіка покривається unit-тестами обов'язково.
6. **Головна сторінка на старті продає кабінет майстрам** (tool first — трафік клієнтів ще відсутній). Клієнтський пошук живе в каталозі. Соціальні докази — тільки справжні: жодних вигаданих лічильників чи порожніх мап.

## Модель даних (ядро)

```
Organization (type: solo | salon | brand)
  └── Location (адреса, гео, робочі години)
        └── Staff (майстер; для solo — один запис)
              └── StaffService (послуга майстра: ціна, тривалість, категорія з таксономії)

ServiceCategory (фіксоване дерево б'юті: nails, brows_lashes, hair, cosmetology, makeup, massage, tattoo_pm, epilation; розширюване)

Client (телефон як основний ідентифікатор, telegram_chat_id, нотатки майстра)
  └── ReliabilityScore (обчислюваний: no-show, пізні скасування)

Booking (client, staff, service, slot UTC,
         status: pending | confirmed | declined | expired | completed | cancelled | no_show)
  └── Review (тільки якщо booking.status = completed — верифікація через візит)

WaitlistEntry (client, staff, бажаний діапазон дат/часу)

ReminderRule (per service: "нагадати через N тижнів після візиту" — двигун Камбекера)

NichePreset (шаблон конфігурації під час онбордингу: категорії, типові тривалості, тексти нагадувань)
```

## Флоу запису (request-to-book)

1. Клієнтка обирає послугу і слот → Booking `pending`, слот блокується (hold) на 2–4 год (налаштовується майстром)
2. Майстру — Telegram-повідомлення з inline-кнопками: **[✅ Підтвердити] [❌ Відхилити] [🕐 Інший час]**. Підтвердження за один тап, без входу в кабінет
3. Клієнтці одразу: "Заявку надіслано, {майстер} зазвичай підтверджує протягом {реальна медіана} хв". Медіана відповіді показується і на публічній сторінці майстра
4. Підтверджено → `confirmed`, сповіщення клієнтці, запис у календарі. Відхилено → `declined` + пропозиція сусідніх слотів. Минув hold → `expired`, слот звільняється, клієнтці — альтернативи
5. Режими майстра: **ручне підтвердження** (дефолт для нових) / **автопідтвердження** для всіх / **автопідтвердження тільки для клієнтів з добрим ReliabilityScore**
6. Нагадування клієнтці за 24 год до візиту; після візиту — статус `completed` і запит відгуку

## Фічі за пріоритетом

### Фаза 1 — MVP кабінету (спринти 1–2)

- [ ] Реєстрація майстра + **AI-імпорт прайсу**: вставив текст прайсу або лінк на Instagram → OpenAI розпарсив у структуровані послуги (категорія, ціна, тривалість) → майстер підтверджує. Кабінет готовий за 60 секунд
- [ ] NichePreset при онбордингу: обрав "манікюр" → готові категорії, тривалості, шаблони нагадувань
- [ ] Публічна сторінка майстра `/@username`: портфоліо, послуги, ціни, кнопка запису
- [ ] Флоу запису request-to-book (див. вище), клієнт без реєстрації (телефон + ім'я)
- [ ] Генерація вільних слотів: робочі години − записи − hold − блокування
- [ ] Telegram-бот: підтвердження в один тап, нагадування за 24 год
- [ ] Адмінка майстра: календар, скасування, перенесення, ручне додавання запису

### Фаза 2 — публічний агрегатор + SEO (спринт 3)

- [ ] Сторінки каталогу `/[misto]/[kategoria]/` (ISR, structured data)
- [ ] Пошук і фільтри: категорія, район, ціна
- [ ] Верифіковані відгуки: запит через Telegram після `completed`
- [ ] Sitemap, robots, метадані, OpenGraph

### Фаза 3 — фічі утримання (Pro-тариф)

- [ ] **AI-Камбекер**: авторозсилка "пора оновити" через N тижнів після візиту з лінком на запис; діалог у месенджері веде до повторного запису
- [ ] Waitlist: при скасуванні бот автоматично пропонує слот черзі
- [ ] Рейтинг надійності клієнта + порада попросити передоплату (для нових/ризикових; без онлайн-оплати)
- [ ] CRM-нотатки про клієнтів, історія візитів
- [ ] Простий облік доходів (без витрат і бухгалтерії)

### Фаза 4 — салони і бренди

- [ ] Спільний календар кількох майстрів, ролі (owner, admin, staff)
- [ ] Аналітика: завантаженість, виручка, no-show rate, рейтинг кожного майстра
- [ ] Мультилокації для брендів
- [ ] Пошук по вільних слотах в агрегаторі ("манікюр сьогодні після 18:00 біля Лівобережної")
- [ ] Direct-автовідповідач в Instagram (лінк на вільні слоти)

### Свідомо НЕ робимо зараз

- Інші вертикалі (СТО, репетитори, клінінг) і resource-based scheduling
- Нативні мобільні застосунки (PWA достатньо)
- ПРРО/фіскалізація, складський облік, програми лояльності, абонементи
- WhatsApp; SMS — лише як платний fallback у майбутньому

## Конвенції коду

- Feature-based структура: `src/features/booking/`, `src/features/catalog/`, `src/features/telegram/`, `src/features/ai-import/`
- Server Actions для мутацій, серверні компоненти за замовчуванням
- Валідація: Zod-схеми, спільні між клієнтом і сервером
- Іменування в коді — англійською; тексти UI — українською, винесені в константи
- Гроші — тільки integer (копійки), ніколи float
- Тести: Vitest; обов'язкове покриття для генерації слотів, hold-логіки, перетинів записів, таймзон
- Комміти: conventional commits (feat/fix/chore)

## Бізнес-правила (важливо)

1. Запис не може перетинатися з іншим записом або активним hold того ж майстра (перевірка на рівні транзакції БД, не тільки UI)
2. Hold діє 2–4 год (конфігурується майстром); `expired` звільняє слот автоматично
3. Відгук — тільки для booking `completed`, один відгук на запис
4. Слоти генеруються з кроком 15 хв, тривалість послуги задає майстер
5. Скасування клієнтом < 3 год до візиту = пізнє скасування (мінус до ReliabilityScore)
6. Телефон клієнта нормалізується до формату +380XXXXXXXXX
7. Free-тариф: 1 майстер, до 30 записів/міс, базові нагадування. Pro: без лімітів + фази 3 фічі (Камбекер, waitlist, порада про передоплату, аналітика)
8. AI-імпорт прайсу: результат парсингу завжди підтверджується майстром перед збереженням; невпізнані позиції потрапляють у категорію "інше" для ручного мапінгу
