# CLAUDE.md — Beauty Booking Platform (робоча назва)

## Що це за проект

Гібридна платформа для б'юті-індустрії України:

1. **SaaS-кабінет** для майстрів, салонів і брендів — букінг, CRM, Telegram-сповіщення (`app.domain.ua`)
2. **Публічний агрегатор** — каталог майстрів і салонів з пошуком, що наповнюється автоматично з даних кабінетів (`domain.ua`)

Стратегія: **tool first, marketplace second**. Кабінет продається за підписку, агрегатор — безкоштовна вітрина для майстрів і джерело SEO-трафіку.

## Технічний стек

- **Framework**: Next.js 15 (App Router), TypeScript strict mode
- **UI**: React, Tailwind CSS, shadcn/ui
- **База даних**: PostgreSQL (Supabase або Neon) + Prisma ORM
- **Auth**: Auth.js (NextAuth v5) — email/password + Google OAuth
- **Сповіщення**: Telegram Bot API (grammY)
- **Платежі**: LiqPay (передоплати клієнтів), пізніше — підписки майстрів
- **Хостинг**: Railway
- **Мова інтерфейсу**: українська (i18n-ready структура, але без перекладів на старті)

## Архітектурні принципи

1. **Одна БД, два фасади.** Кабінет і агрегатор — один Next.js проект (route groups: `(app)` і `(public)`), спільна модель даних.
2. **Публічні сторінки = SEO-актив.** Сторінки `/[misto]/[kategoria]/` і профілі майстрів — SSG/ISR з ревалідацією. Метадані, structured data (schema.org LocalBusiness, Service), sitemap.
3. **Жорстка таксономія послуг.** Кожна послуга майстра прив'язана до категорії з фіксованого дерева (`nails.manicure.gel`), вільна назва — тільки як display name. Без цього не працюють фільтри й пошук агрегатора.
4. **Мультитенантність з першого дня.** Схема підтримує соло-майстра, салон і бренд, навіть якщо UI для салонів з'явиться пізніше.
5. **Таймзони і слоти — тільки через date-fns-tz, все зберігається в UTC.** Календарна логіка покривається unit-тестами обов'язково.

## Модель даних (ядро)

```
Organization (type: solo | salon | brand)
  └── Location (адреса, гео, робочі години)
        └── Staff (майстер; для solo — один запис)
              └── StaffService (послуга майстра: ціна, тривалість, категорія з таксономії)

ServiceCategory (фіксоване дерево: nails, brows, lashes, hair, tattoo, cosmetology, massage...)

Client (телефон як основний ідентифікатор, telegram_chat_id, нотатки майстра)
  └── ReliabilityScore (обчислюваний: no-show, пізні скасування)

Booking (client, staff, service, slot UTC, status: pending | confirmed | completed | cancelled | no_show)
  └── Prepayment (LiqPay, опційна)
  └── Review (тільки якщо booking.status = completed — верифікація через візит)

WaitlistEntry (client, staff, бажаний діапазон дат/часу)

ReminderRule (per service: "нагадати через N тижнів після візиту")
```

## Фічі за пріоритетом

### Фаза 1 — MVP кабінету (спринти 1–2)

- [ ] Реєстрація майстра, онбординг: профіль, послуги, робочі години
- [ ] Публічна сторінка майстра `/@username`: портфоліо, послуги, ціни, кнопка запису
- [ ] Флоу запису клієнта: послуга → вільний слот → підтвердження (телефон + ім'я, без реєстрації)
- [ ] Генерація вільних слотів: робочі години − існуючі записи − блокування
- [ ] Telegram-бот: сповіщення майстру про новий запис, нагадування клієнту за 24 год
- [ ] Адмінка майстра: календар записів, скасування, перенесення, ручне додавання запису

### Фаза 2 — публічний агрегатор + SEO (спринт 3)

- [ ] Сторінки каталогу `/[misto]/[kategoria]/` (ISR, structured data)
- [ ] Пошук і фільтри: категорія, район, ціна
- [ ] Верифіковані відгуки: запит відгуку через Telegram після завершеного візиту
- [ ] Sitemap, robots, метадані, OpenGraph

### Фаза 3 — фічі утримання (кілер-фічі, Pro-тариф)

- [ ] Нагадування "пора оновити": авторозсилка через N тижнів після візиту з лінком на запис
- [ ] Waitlist: при скасуванні бот пропонує слот черзі автоматично
- [ ] Рейтинг надійності клієнта + розумна передоплата (вимагається для нових/ризикових)
- [ ] CRM-нотатки про клієнтів, історія візитів

### Фаза 4 — салони і бренди

- [ ] Спільний календар кількох майстрів, ролі (owner, admin, staff)
- [ ] Аналітика: завантаженість, виручка, no-show rate
- [ ] Мультилокації для брендів
- [ ] Пошук по вільних слотах в агрегаторі ("манікюр сьогодні після 18:00")

### Свідомо НЕ робимо зараз

- Нативні мобільні застосунки (PWA достатньо)
- Складський облік матеріалів
- Програми лояльності
- Інтеграції з касами (ПРРО)

## Конвенції коду

- Feature-based структура: `src/features/booking/`, `src/features/catalog/`, `src/features/telegram/`
- Server Actions для мутацій, серверні компоненти за замовчуванням
- Валідація: Zod-схеми, спільні між клієнтом і сервером
- Іменування в коді — англійською; тексти UI — українською, винесені в константи
- Гроші — тільки integer (копійки), ніколи float
- Тести: Vitest; обов'язкове покриття для генерації слотів, перетинів записів, таймзон
- Комміти: conventional commits (feat/fix/chore), українською або англійською

## Бізнес-правила (важливо)

1. Запис не може перетинатися з іншим записом того ж майстра (перевірка на рівні транзакції БД, не тільки UI)
2. Відгук можливий тільки для booking зі статусом `completed`, один відгук на запис
3. Слоти генеруються з кроком 15 хв, тривалість послуги задає майстер
4. Скасування клієнтом < 3 год до візиту = пізнє скасування (впливає на reliability score)
5. Телефон клієнта нормалізується до формату +380XXXXXXXXX
6. Free-тариф: 1 послуга, 20 записів/міс; Pro: без лімітів + фічі фази 3
